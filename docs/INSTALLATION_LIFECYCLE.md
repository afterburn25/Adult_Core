# Installer lifecycle, one-time setup, and mandatory cleanup

## Directories and routing

- All browser installer files live in **top-level `install/`**, outside the public document root, and are removable as one directory.
- Only `public/index.php` is web-accessible. Apache `public/.htaccess` rewrites `/install/`, `/admin` and frontend routes to that single entry point. There is **no** `public/install` script and no direct access to the top-level `install/` directory.
- `src/Installer/InstallationGate.php` determines whether the router is in setup, cleanup, ready or error state.
- Installation completion requires a valid signed `storage/install-state.json` and private `config/app-key.php` and `config/database.php`. All three files are **outside** the public root and gitignored.

## Fail-closed state machine

| Condition | State | HTTP behavior |
|---|---|---|
| No completion marker, `install/` exists | `setup_required` | `/` and `/admin` redirect to `/install/`; setup form appears if eligible |
| Valid signed marker and config, `install/` exists | `cleanup_required` | HTTP 503 for ALL routes; manually delete `install/` |
| Valid signed marker and config, `install/` absent | `ready` | Gate enables administrator login and authenticated dashboard; public membership website still shows HTTP 503 |
| Marker missing and `install/` absent | `installer_missing` | HTTP 503; restore matching installer |
| Marker malformed/unsigned/tampered, key/database config absent | `invalid_state` | HTTP 503; restore trusted backup |

Completion marker schema (generated by installer, **do not hand-create**):

```json
{
  "schema_version": 2,
  "status": "complete",
  "edition": "lite",
  "installed_at": "2026-11-20T00:00:00Z",
  "signature": "<64-character HMAC-SHA256 hex signature>"
}
```

The signature uses the unique app key in private `config/app-key.php`. The completed marker is **written last** only after database migrations, first admin creation, persisted edition and verification succeed.

## Browser sequence

1. Preflight checks PHP/extensions, writable private storage and a safe web document root. The Cajun Web Pro product-bound license key selects Lite or Pro; independently verified server capabilities (including authenticated Pro agent for Pro) may block installation, but never change the licensed edition.
2. Operator creates a **fresh empty database** in cPanel/hosting control panel and supplies new DB credentials, site name and first admin credentials over HTTPS.
3. Browser POST must carry a valid installer CSRF token. Session cookies are HttpOnly/SameSite, and the action is IP-rate-limited. Both the browser controller and the installation service validate that the registered license hostname matches the HTTP request hostname (www/apex normalized); a mismatch fails before contacting the license issuer or creating any MySQL tables. CLI integration fixtures do not have a browser origin and remain separate from live web installation acceptance. Server capabilities are checked again.
4. Installer obtains an exclusive filesystem lock; verifies installation isn't already complete, independently revalidates database connection fields, administrative credentials and licensing inputs at the service boundary (even when invoked outside the browser), and refuses to overwrite private config or existing `ac_` schema tables.
5. Installer creates the initial schema, hashes the first admin password, inserts admin/settings/edition/migration records and verifies tables/admin presence.
6. Installer generates private configuration and app secret via atomic owner-only writes, then writes the signed completion marker as the **final state mutation**.
7. Installer redirects to the cleanup-required screen. ALL public/admin requests remain HTTP 503 until the operator **manually deletes the entire top-level `install/` folder** using File Manager or SSH.
8. After folder removal, the gate reaches ready. M3 provides `/admin/login` and an authenticated read-only dashboard; the public site remains disabled until membership and compliance work is complete.

## Recovery and security

- Deleting `install/` **before** successful setup never unlocks the site.
- Unrecognized/unsigned state files cannot bypass setup or cleanup.
- MySQL **DDL is not transactional**: failures during table creation may leave a partial schema. The installer **refuses existing `ac_` tables** rather than deleting or overwriting anything. Recover with a trusted backup or a newly created empty database after an operator reviews the failure.
- If configuration writing fails after database bootstrap, some schema may exist without a completion marker; this is still a blocked installation. Do not bypass the gate or delete the marker to restart.
- Keep `config/`, `src/`, `install/` and `storage/` inaccessible from the web. HTTPS is required for real hosting. Never put secrets in logs, URLs, code comments or Git commits.
- This is not yet deployable for live membership service; security reviews, verified adult-age/consent workflows, billing compliance, real login and protected private media are upcoming milestones.
